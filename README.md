Deskflow DDC 是适合两台电脑共用一块显示器的桌面应用。使用 **Rust + Tauri 2 + Vue 3**，内置 **Deskflow 1.27.0**，无需另行安装键鼠共享引擎。实体键鼠可以连接在任意一端，按提供端和接收端配置，不绑定操作系统。

**0.2.4** · [下载安装包](https://github.com/Fantasy1316/deskflow-ddc/releases) · [更新说明](CHANGELOG.md) · [反馈问题](https://github.com/Fantasy1316/deskflow-ddc/issues)

这是独立项目，与 [Deskflow](https://github.com/deskflow/deskflow) 官方无隶属关系。

## Windows 锁屏与密码界面

普通模式无需管理员权限，但不能控制 Windows 密码输入安全桌面。需要此功能时，在 Windows 接收端停止共享，进入“共享设置 → 锁屏与登录界面控制”，安装后台服务，允许系统管理员授权，再开启“允许控制安全桌面”、保存并重新共享。安全桌面模式只使用内置引擎。

连接 Windows 接收端后，可在提供端工作台或托盘选择锁屏。键鼠切到 Windows 时，也可按提供端键盘上的 **Ctrl + Alt + Shift + L**（Mac 的 Alt 为 Option）。按钮通过已配对连接请求 Windows 锁屏；快捷键同时支持接收端处理，并跟随修饰键映射，不依赖模拟 Win + L。

服务按需启动，不保存登录密码，不自动恢复上一次共享。停止共享、应用退出、连接租约失效时会停止所属引擎；其他 Deskflow 实例不会被接管。应用升级后需更新服务。便携版删除前请先移除服务；安装版通过安装/卸载流程清理服务。拒绝管理员授权时仍可使用普通模式。

当前仅覆盖已登录用户的锁屏后控制，不包含开机首次登录、注销后登录或 BitLocker 界面；不模拟 Ctrl + Alt + Delete，要求该组合键才能登录的电脑需先在 Windows 本机完成此步骤。不同 Windows 版本、系统策略及安全软件可能影响控制效果，请在需要的界面验证。

## 功能

- **仅切换显示器**：不需要局域网或配对，不启动 Deskflow；通过本机按钮、托盘或快捷键发送 DDC 输入源指令。

- **画面与键鼠切换**：快捷键、应用按钮和托盘菜单协调键鼠与显示器输入源切换。
- **默认手动切换画面**：鼠标碰到边缘不切换输入源，避免日常操作误切屏；自动跟随模式可以主动开启。
- **屏幕布局与跨屏**：拖动电脑图块设置方向。目标有独立屏幕时可只转移键鼠，让共用显示器保持当前画面。
- **内置键鼠引擎**：随包提供固定版本的 Deskflow 及运行库，启动时使用隔离的配置和证书。
- **主机名连接与 IP 兜底**：支持 mDNS 发现、可解析主机名、手动备用 IP 和上次已认证地址。
- **跨系统修饰键映射**：可将 Mac Command 与 Windows Ctrl 对应，统一复制、粘贴等快捷键；仅影响远程接收端。
- **剪贴板共享**：可开关并设置容量；图片和富文本兼容性取决于 Deskflow 与两端系统。文件传输使用独立通道，不依赖剪贴板。
- **文件与目录传输**：支持大文件、压缩包及完整目录，接收确认、加密直传、暂停续传和 SHA-256 校验。
- **托盘与诊断日志**：后台共享、快速停止、导出两端日志。
- **退出保护**：退出时等待本应用的键鼠引擎结束；macOS 增加独立守护进程，在主应用异常结束后清理其所属引擎。

## 系统与硬件要求

| 项目    | 要求                                                                           |
| ------- | ------------------------------------------------------------------------------ |
| macOS   | Apple Silicon，macOS 14 或更新版本；暂不支持 Intel Mac 的 DDC 控制             |
| Windows | Windows 10 / 11 x64，需要 Microsoft Edge WebView2 Runtime                      |
| 显示器  | 开启 DDC/CI，并支持通过 VCP `0x60` 切换输入源                                  |
| 接线    | 两台电脑分别连接共用显示器的不同输入接口                                       |
| 网络    | 完整共享需要两台电脑网络互通；仅切换显示器无需网络，完整共享允许控制与键鼠端口 |

Ubuntu 24.04 的 X11 适配正在实验性开发，尚未完成 Ubuntu 实机验证；当前已发布的 0.2.4 安装包不包含 Linux 支持。跨系统测试需两端均使用包含本次适配的构建，不能仅更新 Ubuntu 端。Ubuntu 可以作为提供端或接收端，与另一台 Ubuntu、Windows 或 Mac 使用相同角色配置。Wayland 暂不支持完整共享，仅可尝试本机 DDC 切屏；虚拟显示器通常不提供真实 DDC/I²C 通道。

支持范围内的两台 Windows、两台 Mac 或 Windows / Mac 混合均按相同角色配置。显示器、扩展坞、转接器和线材会影响 DDC/CI；使用前请分别确认两端都能发送输入切换指令。

## 安装

1. 从 [Releases](https://github.com/Fantasy1316/deskflow-ddc/releases) 下载对应系统的版本，两端使用相同版本。
2. macOS 解压后打开 `Deskflow DDC.app`；Windows 使用安装程序，或完整解压便携包后运行 `Deskflow DDC.exe`。便携包内 DLL 和 `resources` 必须一起保留。
3. 开始共享前，停止旧版及独立 Deskflow 的共享，避免引擎和端口冲突。应用不会接管其他程序启动的引擎。
4. macOS 按系统提示授权辅助功能或输入监控；修改后可在应用中重新检测。主应用检测通过不代表内置 Deskflow 引擎也已获授权。
5. Windows 允许应用通过所用网络的防火墙；未安装 WebView2 时需先安装运行时。

项目当前默认构建不提供 Developer ID 公证或 Windows 发行签名，系统可能提示未知开发者。仅使用可信来源的包；具体签名情况以对应 Release 为准。

## 快速开始

### 配置显示器输入源

两端分别进入 **显示器与输入**，扫描并选择共用显示器，填写本机与另一台对应的输入源数值并保存。

例如，电脑 A 的输入源实测值为 `3`，电脑 B 为 `1`：

| 电脑 | 本机输入源 | 另一台输入源 |
| ---- | ---------- | ------------ |
| A    | 3          | 1            |
| B    | 1          | 3            |

以上只是示例，**请填写实际验证过的值**，不要仅凭 HDMI、DVI 或 VGA 名称推断。两端显示器 ID 可以不同，需各自扫描选择。

停止共享后，可使用“单独测试显示器切换”验证映射。测试会立即改变画面；必要时用显示器实体按键恢复。

### 仅切换显示器（无需网络）

在 **工作台 → 运行模式** 选择 **仅切换显示器**，配置并保存本机显示器及两个不同的输入源，然后点击 **启用显示器切换**。之后可通过工作台、托盘菜单或设置的本机快捷键切换；本模式不转移键鼠，不启动 Deskflow，也不要求另一端安装或运行应用。停止后可修改设置或切回完整共享，原配对与键鼠设置保留。重启应用后需要手动启用。

所有指令由本机发送。**部分显示器仅接受活动输入端的 DDC 指令，可能只能切出去、无法从本机切回来**，使用前请测试两个方向；必要时用显示器实体按键恢复。快捷键会优先读取当前输入值；读不到时按最近发送的目标交替，首次默认切到另一输入。画面指令成功不代表实际画面已确认。

### 选择角色并配对（完整共享）

1. 在 **设备与配对** 中，实体键鼠所在的电脑选择 **连接在这台电脑**，作为提供端；另一台选择 **连接在另一台电脑**，作为接收端。
2. 先让共用显示器显示提供端画面，提供端点击 **开始等待连接**。
3. 接收端点击 **查找设备** 选择提供端，也可填写提供端的可解析主机名或 IP，并配置备用 IP。
4. 保存设备设置，填写提供端配对码，点击 **配对并开始共享**。
5. 等待工作台显示引擎就绪，再尝试双向切换。

配对成功后会保存配对凭据。再次启动共享时，接收端可将配对码留空，点击 **开始共享**；重新生成配对码、导入旧版配置或更换配对设备后需重新配对。

默认控制端口为 **TCP `49729`**，键鼠端口为 **TCP `24801`**。mDNS 发现使用 **UDP `5353`**。

默认切换快捷键：macOS 为 **`Ctrl + Option + F10`**，Windows 为 **`Ctrl + Alt + F10`**。Mac 是否需要加 `Fn` 取决于功能键设置。Windows 的 `F12` 不适合作为全局切换键。停止共享后可在 **共享设置** 修改快捷键。

### 开机自启动与自动共享

在 **共享设置 → 启动与后台运行** 中分别开启选项，点击 **保存启动设置**。两项默认关闭，共享期间也可修改。

- **开机自启动**：用户登录系统后在后台启动到托盘，不自动打开主界面。Mac 使用用户级 LaunchAgent，Windows 使用当前用户的登录启动项，Ubuntu 使用当前用户的 XDG 自动启动项；不需要安装新的后台服务。
- **启动后自动共享**：完成一次配对后，每次打开应用按已保存配置等待或连接已配对的电脑；无需再次填写配对码。仅切屏模式则自动启用本机显示器控制。

对端尚未上线或网络未恢复时，已启动的共享会保持等待并自动重试连接。配置不完整、权限缺失或 Windows 后台服务需要更新时会提示处理，不跳过检查。手动停止共享后，本次运行保持停止；完全退出并重新启动应用后，才再次执行自动共享。关闭主界面仍在托盘运行，彻底退出请使用托盘菜单。

登录启动只在进入用户桌面后生效，不提供开机首次登录界面的控制。请先把 Mac 应用或 Windows 便携版放到固定位置再开启；移动、删除应用前先关闭开机自启动，移动后重新开启。系统中修改启动项后可回到应用点击 **重新检测**。

### 跨系统修饰键映射

停止共享，在键鼠提供端进入 **共享设置 → 跨系统修饰键映射**，选择模式、保存并重新开始共享。接收端自动使用提供端的设置。

- **保持原始按键（默认）**：跨系统时 Command 对应 Win，Control 对应 Ctrl。
- **统一常用快捷键**：Mac 提供键鼠时，Command 对应 Windows Ctrl、Control 对应 Win；Windows 提供键鼠时，Ctrl 对应 Mac Command、Win 对应 Control。例如使用 Mac 键盘控制 Windows 时，`Command + C / V` 可用于复制 / 粘贴。

映射仅在 Mac 与 Windows / Linux 之间转发输入时生效；Windows 与 Linux 之间保持 Ctrl 和 Win / Super 原样，同系统共享及本机操作保持原样。这会交换所有相关组合键；`Command + Tab` 与 `Alt + Tab` 等按键组合不同的操作仍需遵循目标系统规则。

### 配置鼠标跨屏

停止共享，在提供端进入 **共享设置 → 屏幕布局与鼠标跨屏**，拖动电脑图块设置相对方向。接收端连接后使用提供端布局。

- **画面仅手动切换（默认）**：边缘不切换输入源，只向有可见屏幕的电脑转移键鼠。两端都只有共用显示器时，通过快捷键或按钮切换。
- **跟随键鼠切换画面**：越过指定边缘时同时切换画面和键鼠。
- **目标有独立屏幕时仅转移键鼠，否则切换画面**：进入有独立屏幕的电脑时，共用显示器保持原输入。

有内置屏或另一块独立显示器的电脑，需要在本机设置中选择该屏幕；不要把共用显示器选为独立屏幕。例如共用显示器显示 Windows 时，Mac 已选择内置屏，就可以从 Windows 按布局滑回 Mac 内置屏，仅转移键鼠。

Windows 独立屏幕按显示设备接口标识保存，同一设备仅发生句柄或屏幕编号变化时可继续识别。旧版保存的数字句柄无法可靠迁移，请重新选择独立屏幕并保存；更换接口、扩展坞或重装驱动导致设备标识改变时，也需要重新选择。

共享期间，所选独立屏幕因睡眠或热插拔暂时消失时，应用会暂停键鼠引擎并保持等待，检测到屏幕恢复后自动重试连接。显式停止共享后不会自动开始；停止与重新开始会保留最近一次画面指令的目标，避免从错误的电脑发送 DDC 指令。

### 文件与目录传输

从 0.2.4 起提供此功能，两端均需更新到相同版本。

1. 两台电脑先完成配对并保持连接，进入 **文件传输**。
2. 发送端将文件或整个目录拖入发送区域，或点击区域打开系统文件选择器（支持多选；文件夹直接拖入）。压缩包作为普通文件传输，不自动解压。
3. 接收端确认邀请并选择保存位置。文件或目录按原名直接保存到所选位置，保留原目录结构、空目录和空文件；同名时由你选择替换、保留两者或停止。
4. 传输列表提供进度、速度、当前文件、暂停、继续、取消和打开接收目录。

传输采用分块流式读写，不将整个文件读入内存。文件传输使用独立线程池；控制连接延迟明显升高时，会自动降低文件发送速率，延迟恢复后逐步提速。该措施用于减少对键鼠共享的影响，不能保证拥塞 Wi-Fi 下完全无延迟。每个文件都需完成 SHA-256 校验和同步落盘后才确认；全部校验完成后，按原名直接保存到所选位置，不再增加外层任务目录。同名文件或目录由接收端逐项选择“替换”“保留两者”或“停止操作”；目录替换是整体替换，不合并旧目录。停止操作会保留续传缓存，并保持原有项目不变。传输中使用所选位置下的 `.deskflow-ddc-任务ID.partial` 缓存，请勿修改或移动它。

短暂连接故障会自动重试；仍无法连接时保留缓存并暂停。暂停或重启应用后，发送端点击原任务的 **重新发送此任务**，接收端再点击 **继续接收**；无需重新选择源文件。续传会检查缓存前缀，发现损坏则重传对应文件。源文件修改或移动后需取消原任务并重新选择发送。

**取消接收**会删除该任务的未完成缓存，已完成结果保留。**移除记录**仅清理任务记录，不删除接收文件。更换配对凭据会停止旧传输；退出应用会暂停未完成任务。传输独立于键鼠引擎，停止键鼠共享不会中止已建立的文件传输，请在文件传输页单独暂停或取消；切换到“仅切换显示器”模式会暂停全部未完成文件任务并释放传输端口。

- 文件内容通过独立加密 TCP 通道直接传输；发送端会临时监听系统分配的 TCP 端口，需在两端防火墙中允许 Deskflow DDC 应用网络访问。仅放行固定控制端口不足以传输文件。
- 每批最多 100000 个文件和目录、64 层目录，一次最多选择 256 个根项目；单文件使用 64 位大小，不受 4 GiB 限制，但仍受目标文件系统容量和格式限制（如 FAT32）。最多同时运行 4 个任务，保留 100 个任务记录。
- 不支持符号链接、Windows 目录联接或设备等特殊文件；不兼容的跨系统文件名会在传输前报错。
- 当前传输文件内容和目录结构，不保留文件权限、扩展属性、资源叉等系统专属元数据，不作为系统备份工具。
- 当前不提供系统文件复制粘贴或跨屏文件拖拽。

### 托盘与退出

macOS / Windows 左键单击托盘图标打开主界面；右键菜单提供 **打开主界面、切换到本机、切换到另一台、停止共享、退出**。

Ubuntu 的托盘点击行为由桌面环境决定，可从菜单打开主界面；GNOME 需要启用 AppIndicator 扩展。若托盘不可用，关闭窗口会退出，避免留下无法打开的后台进程。

关闭窗口仅隐藏到托盘，后台共享继续；macOS 同时隐藏 Dock 图标，从托盘打开时恢复。要释放键鼠共享，选择 **停止共享**；要结束应用，选择 **退出**。若托盘创建失败，关闭窗口会走退出流程。

macOS 也支持从 Dock 右键选择 **退出**。应用会等待所属引擎停止后完成退出；系统注销或关机时使用同样的清理流程。主应用异常结束时，独立守护进程按进程身份清理所属引擎，不扫描或结束其他程序的引擎。这项保护不等同于键鼠无响应时的独立紧急停止功能。

页面不显示浏览器右键菜单。主机名、IP、已显示的配对码、错误信息与活动记录可选中复制；输入框保留系统复制、剪切与粘贴快捷键。

## 从旧版升级

0.2 与 0.1 使用独立配置、身份和凭据，不自动覆盖旧版数据。保留旧应用时应放在不同位置，并先停止旧版共享。

**设备与配对 → 导入旧版配置** 可以读取旧版 `settings.json`，导入前会备份当前配置。仅导入设备设置，不复制旧配对密钥与证书；导入后需要重新配对，并核对显示器、独立屏幕及快捷键。

0.2.4 沿用 0.2 系列的数据目录和凭据，从 0.2.0、0.2.1、0.2.2、0.2.3 或 0.2 预览版升级会保留配置和配对。两端必须同时升级到 0.2.4；对端版本不同或未提供版本号时，应用会阻止启动键鼠引擎。较早版本的跨屏模式会一次性设为默认手动画面模式，并保存原配置备份。

升级前请先停止共享，并通过应用或托盘菜单退出两端旧版，再更新。若使用 Windows 安全桌面服务，升级后需在共享设置中安装/更新后台服务。无需卸载旧版或删除配置。

## 常见问题

**查找不到设备，或 IP 变动后无法连接**

mDNS 通常只在同一子网有效。跨子网、访客 Wi-Fi、客户端隔离或代理/VPN 路由可能阻止发现；TCP 可连接也不代表组播能到达。此时填写可解析的主机名与备用 IP，必要时设置路由器 DHCP 地址保留。

每次重连会重新解析主机名，随后尝试已配对设备的发现地址、手动备用 IP、上次已认证地址。所有候选地址都必须通过身份校验；旧 IP 无法保证在设备地址变化后仍可用。

**一直显示“引擎连接中”**

检查两端版本、端口、防火墙与系统权限，并退出独立 Deskflow。控制连接建立不代表键鼠引擎已就绪。0.2.4 会阻止与版本不同或未提供版本号的旧端启动键鼠引擎，请同时更新两端。

**输入源写入失败，或提示画面状态不确定**

检查 DDC/CI、当前输入、线材和扩展坞。部分显示器只接受活动输入端的 DDC 指令。指令发送成功也不能证明物理画面已经切换。状态不确定后请停止共享，使用实体按键恢复提供端画面，再重新连接。

**鼠标能动，但无法点击或键盘无响应**

当前存在输入捕获后无法操作的报告，原因尚未确定。有另一台可操作的电脑时，优先在那一端选择 **停止共享**。关闭主窗口不会停止共享。

引擎内置的返回提供端按键为 Windows `Ctrl + Alt + Esc`、Mac 提供端 `Ctrl + Command + Esc`，只请求转移键鼠，不保证恢复显示器输入；引擎失去响应时该按键也可能失效。Windows 可尝试 `Ctrl + Alt + Delete` 进入安全界面；仍无法操作时需要通过可用的本机或远程管理手段结束对应引擎。项目尚未提供独立于引擎的紧急停止机制。

**如何反馈问题**

在两端分别进入 **活动记录 → 导出诊断日志**，附上系统版本、应用版本、接线方式、角色和复现步骤。日志包含设备名、局域网地址、配置摘要和文件任务信息，分享前请检查。文件诊断还包含加解密、网络等待、读写、校验、同步落盘及主动降速耗时，帮助区分传输瓶颈。不要公开配对码、私钥或完整配置文件。

## 隐私与限制

- 应用直接连接另一台电脑，键鼠和剪贴板由 Deskflow 传输，不提供云中转。
- 配对密钥使用 macOS 钥匙串、Windows 凭据管理器或 Linux Secret Service（GNOME Keyring）；引擎私钥存放在应用数据目录。
- 本应用不记录按键内容、鼠标轨迹或剪贴板内容；诊断日志会过滤配对码等敏感信息。
- 文件任务记录仅保存在本机，包含文件名、源路径、大小和保存位置，以支持重启续传；不保存文件通道的临时密钥。接收需用户确认，文件内容不进入诊断日志。
- 当前支持一对一共享，不提供远程桌面视频、USB 转发或自动唤醒。
- 锁屏、UAC 安全桌面、睡眠恢复及不同 DPI 的跨屏行为受操作系统和引擎限制。

## 从源码构建

需要 Node.js 22.13+、pnpm 11、Rust 1.90+ 和目标系统的 Tauri 构建环境。macOS 使用 Apple Silicon 与 Xcode Command Line Tools；Windows 使用 Visual Studio C++ Build Tools 和 Windows SDK。

```sh
pnpm install --frozen-lockfile
pnpm prepare:engine
pnpm pack:mac  # 在 macOS 上构建 .app
# pnpm pack:win  # 在 Windows 上构建安装包
```

首次准备引擎需联网下载并校验官方资源。产物位于 `src-tauri/target/release/bundle/`，需完整分发内置运行库、源码及许可材料。

### Ubuntu 实验性构建与配置

首个验证目标为 **Ubuntu 24.04 x86_64 + X11**，提供 `.deb`。Linux 核心也接受 ARM64 架构，但 ARM64 的完整包尚未验证；Apple Silicon 上的 Ubuntu ARM64 虚拟机不能代替 x86_64 安装包验证。

使用 `.github/workflows/ubuntu.yml` 可在 GitHub Actions 构建 Ubuntu 包，并在 Xvfb 虚拟显示器中执行输入桥读取测试。该流程不发布 Release，不测试真实输入捕获或物理 DDC。构建脚本从固定 SHA-256 的 Deskflow 1.27.0、libei 1.3.0 和 libportal 0.9.1 源码编译；Qt 固定为 6.8.3，附带动态运行库、对应 qtbase 源码和许可。不能直接复制较新 Ubuntu 的官方 Deskflow 二进制到 24.04。

本地构建需先安装 Qt 6.8.3（包含 qtbase、Qt Widgets、Network、DBus 和 LinguistTools），将其 `bin` 加入 `PATH` 并设置 `CMAKE_PREFIX_PATH`。可用 Qt 安装器；x86_64 也可通过 `aqtinstall` 安装 `linux desktop 6.8.3 linux_gcc_64`。其他构建依赖及 apt 包列表以该工作流为准。然后运行：

```sh
pnpm install --frozen-lockfile
pnpm prepare:engine
pnpm pack:linux
```

安装 `.deb` 时使用 `sudo apt install ./实际文件名.deb`，由 apt 安装 ddcutil、WebKitGTK、托盘等系统运行依赖。应用和 Deskflow 均以当前用户运行，不要求 root。首次运行需在已登录且钥匙环解锁的桌面中进行。

显示器控制使用 Linux DRM / EDID 识别显示器，每次操作重新解析 I²C 总线；不保存临时总线号或 RandR 句柄。若没有显示器、无法读写 DDC 或提示权限不足，请先检查：

```sh
sudo modprobe i2c-dev
sudo usermod -aG i2c "$USER"
# 注销并重新登录后，再运行：
ddcutil detect
ddcutil getvcp 60
```

若系统没有 `i2c` 组，需先按发行版规则配置设备访问权限；应用不会自动创建规则或提权。需要每次开机加载模块时，可按系统管理要求配置 `modules-load.d`。读取失败不等于显示器不支持写入；必须分别测试切出和切回。虚拟机通常只能验证界面、网络、文件传输和 X11 基础行为，真实 DDC、睡眠恢复、热插拔、锁屏及双机键鼠仍需实机测试。Ubuntu 当前不提供 Windows 安全桌面服务的对应能力。
