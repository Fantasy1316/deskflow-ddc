Deskflow DDC 面向两台电脑共用一块显示器的工作场景，内置 **Deskflow 1.27.0**，无需另行安装键鼠共享引擎。实体键鼠可以连接在任意一端，Mac、Windows 和 Ubuntu 按提供端、接收端配置，不绑定操作系统。

**版本 0.3.0** · [下载安装包](https://github.com/Fantasy1316/deskflow-ddc/releases) · [更新记录](CHANGELOG.md) · [反馈问题](https://github.com/Fantasy1316/deskflow-ddc/issues)

这是独立项目，与 [Deskflow](https://github.com/deskflow/deskflow) 官方无隶属关系。应用使用 Rust、Tauri 2 和 Vue 3；英文文档不代表应用界面已提供英文翻译。

## 功能

- **画面与键鼠切换**：通过快捷键、工作台按钮或托盘菜单协调两端切换。
- **仅切换显示器**：不需要网络、配对或运行 Deskflow，使用本机 DDC 控制输入源。
- **默认手动切屏**：鼠标碰到边缘不切画面；可主动开启画面跟随，或只在独立屏幕之间转移键鼠。
- **不支持 DDC 时的可选兜底**：macOS / Windows 可尝试断开输出、触发显示器自动选源，仍属实验性功能。
- **主机名与 IP 兜底**：设备发现、主机名重解析、备用 IP 和已认证地址缓存。
- **跨系统快捷键与剪贴板**：可统一 Mac Command 与 Windows Ctrl，并设置剪贴板共享及容量。
- **文件与目录传输**：大文件、目录和压缩包加密直传，支持接收确认、暂停续传、SHA-256 校验和重名处理。
- **登录启动与自动共享**：两个选项独立配置，默认关闭。
- **状态与恢复**：切换进度、画面来源确认、托盘提醒、恢复输出和两端诊断日志。
- **Windows 安全桌面控制**：可选后台服务，用于已登录用户锁屏后的密码 / PIN 输入界面。

## 支持范围

| 平台    | 要求                                                 | 安装包 / 状态                              |
| ------- | ---------------------------------------------------- | ------------------------------------------ |
| macOS   | Apple Silicon，macOS 14+                             | 应用压缩包；暂不支持 Intel Mac 的 DDC 控制 |
| Windows | Windows 10 / 11 x64，Microsoft Edge WebView2 Runtime | 安装程序；便携包以对应 Release 为准        |
| Ubuntu  | Ubuntu 24.04，x86_64 / ARM64，X11                    | **Beta（实验性）**，DEB 安装包             |

两台电脑需分别连接显示器的不同视频输入接口。完整共享需要两端网络互通；仅切换显示器无需网络。相同系统之间也可配对，不限于 Mac + Windows。

Ubuntu Beta 暂不支持 Wayland / XWayland 完整共享、安全桌面控制或断开输出兼容模式。ARM64 虚拟机已验证应用可启动，真实双机键鼠、物理 DDC、睡眠恢复等仍需实机验证，不应视为与 macOS / Windows 同等成熟。

## 先确认显示器能否切换

DDC 模式需要显示器开启 **DDC/CI**，并支持通过 **VCP `0x60`** 切换输入源。

1. 在显示器实体菜单中查找并开启 DDC/CI。不同品牌名称和位置可能不同。
2. 两端分别进入应用的 **显示器与输入**，扫描并选择共用显示器。
3. 停止共享，使用 **单独测试显示器切换** 验证两端能否切出和切回；必要时使用显示器实体按键恢复画面。

**能识别显示器、能读取亮度，均不代表支持输入源切换。读不到当前输入值，也不能直接断定不支持写入。** 线材、扩展坞和转接器会影响 DDC，部分显示器仅接受当前活动输入端发送的指令，请分别验证两个方向。

如果 DDC 确实不可用，可尝试下方的实验性兼容模式；不支持自动选源的显示器仍需要实体按键或硬件切换器。

## 安装与升级

1. 从 [Releases](https://github.com/Fantasy1316/deskflow-ddc/releases) 下载对应系统和架构的包，完整共享的两端均使用 **0.3.0**。
2. 更新前，先停止共享并退出两端旧应用和独立 Deskflow。应用不会接管其他程序启动的引擎。
3. macOS 解压后将 `Deskflow DDC.app` 放到“应用程序”再打开，按提示授予辅助功能 / 输入监控权限。修改权限后可在应用内重新检测；主应用检测通过不代表内置引擎也已获授权。
4. Windows 运行安装程序，或完整解压便携包后运行 `Deskflow DDC.exe`。保留随包 DLL 和 `resources`，允许应用通过所用网络的防火墙；未安装 WebView2 时需先安装运行时。
5. 已启用 Windows 安全桌面控制的用户，升级后还需在共享设置中 **安装 / 更新后台服务**。

0.3.0 沿用 0.2 系列的配置、设备身份、配对凭据和启动设置，无需删除配置。0.1 使用独立数据；可在 **设备与配对 → 导入旧版配置** 导入设备设置，导入后需重新配对并核对显示器映射。

项目当前不提供 Developer ID 公证或 Windows 发行签名，系统可能提示未知开发者；具体情况以对应 Release 为准，请仅使用可信来源的安装包。

## 快速开始

### 1. 配置两端输入源

两端分别扫描共用显示器，填写本机和另一台电脑对应的实际输入值，并保存。例如 A 实测为 `3`、B 实测为 `1`：

| 电脑 | 本机输入源 | 另一台输入源 |
| ---- | ---------- | ------------ |
| A    | 3          | 1            |
| B    | 1          | 3            |

这些数值仅为示例，**不要仅凭 HDMI、DP、DVI 或 VGA 名称推断输入值**。两端的显示器 ID 可以不同，应各自扫描选择。

### 2. 选择角色并配对

1. 在 **设备与配对** 中，实体键鼠所在的电脑选择 **连接在这台电脑**，作为提供端；另一台选择 **连接在另一台电脑**，作为接收端。
2. 先让显示器显示提供端画面，提供端点击 **开始等待连接**。
3. 接收端点击 **查找设备** 选择提供端，或填写可解析主机名 / IP、备用 IP。
4. 保存设置，填入提供端的完整配对码，点击 **配对并开始共享**。
5. 工作台显示引擎就绪后，测试双向切换。

配对凭据会保存。再次启动时接收端可留空配对码；更换设备、重新生成配对码或导入旧配置后需重新配对。

### 3. 切换画面与键鼠

默认快捷键为 macOS **`Ctrl + Option + F10`**、Windows **`Ctrl + Alt + F10`**。Mac 是否需加 `Fn` 取决于功能键设置。停止共享后可在 **共享设置** 中修改。

DDC 模式在连接后主动读取输入源，并匹配两端配置；读取失败或结果冲突时，请按实际画面确认当前来源。**确认来源仅更新记录，不切屏、不转移键鼠。** 键鼠位于哪一端，不能证明显示器实际显示哪一端。

切换期间和等待显示器稳定时，重复切换请求会被拦截，避免边缘往返或连续按键触发来回切屏。短暂读不到切源后的输入值，不会仅因此撤销已完成的键鼠转移；若提示画面来源不确定，请核对实际画面并使用明确目标的按钮处理。

### 仅切换显示器

在 **工作台 → 运行模式** 选择 **仅切换显示器**，保存本机显示器和两个不同的输入源，点击 **启用显示器切换**。本模式不转移键鼠，也不要求另一端安装或运行应用。

指令全部由本机发送。部分显示器只能切出去，无法从非活动输入端切回来，请先测试两个方向。快捷键会结合当前读数和最近指令选择目标，避免旧读数使切换一直停留在同一方向。

## 不支持 DDC 时的兼容模式（实验性）

此模式尝试停用原电脑的视频输出，让显示器自行选择另一台电脑。**它依赖显示器的自动选源能力，并非所有设备都能替代 DDC。**

1. 在显示器实体菜单中开启自动选择输入源。
2. 两端选择完整共享，在 **显示器与输入 → 切屏方式** 选择 **断开输出，触发显示器自动选源**。
3. 各自扫描、选择允许断开的本机共用输出并保存；扫描和条件检测不会切断输出。
4. 两端配对连接后，按实际画面确认当前显示的是本机还是另一台，再用快捷键或按钮切换。

| 平台                | 条件与限制                                                                                                         |
| ------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Apple Silicon macOS | 无需安装 BetterDisplay；必须保留内置屏或另一块活动屏幕，不支持镜像输出。系统接口可能受 macOS 更新影响。            |
| Windows             | 仅支持一块活动外接显示输出；多屏、镜像或内置屏场景不支持。实体输入或其他软件可能提前唤醒输出，恢复速度取决于设备。 |
| Ubuntu              | 暂不支持。                                                                                                         |

切换按“恢复目标输出 → 转移键鼠 → 停用原输出 → 保留确认”执行，不修改 EDID。切换流程完成会记录最近目标，但软件无法直接验证显示器的实际输入。首次连接、重连或唤醒后来源不确定时，需要重新确认；鼠标碰到边缘不会触发断开输出。

主界面隐藏到托盘时，未确认来源会通过托盘旁的原生浮窗提醒。浮窗不会因失去焦点关闭，可手动关闭或选择稍后确认；未确认时再次尝试切换或重新隐藏到托盘会再次提醒，也可从托盘菜单选择 **确认当前画面…**。

切换失败、停止共享、断线、唤醒或退出时会请求恢复输出；主应用异常结束时，独立守护进程也会尝试恢复。**恢复失败后，主界面和托盘保留“恢复本机显示输出”入口，停止或断线后仍可重试。** 共享运行中使用该入口会先停止共享。

请先测试切出和切回，并保留显示器实体按键、本机键鼠和重新插拔视频线等恢复方式。自动选源和恢复效果依赖具体显卡、显示器、线材、扩展坞及驱动，请以双向实测为准。

## 跨屏、快捷键与后台运行

- **鼠标跨屏**：在提供端的共享设置中拖动电脑图块配置方向。默认画面仅手动切换；也可启用画面跟随，或在目标有独立屏幕时仅转移键鼠。带内置屏或独立屏幕的电脑需在本机选中该屏幕，不要选共用显示器。独立屏幕睡眠或热插拔暂时消失时，应用会暂停引擎，屏幕恢复后重试连接。
- **跨系统修饰键**：默认 Command 对应 Win、Control 对应 Ctrl；启用“统一常用快捷键”后，Mac 提供端的 Command 对应 Windows Ctrl，Windows 提供端的 Ctrl 对应 Mac Command。同系统和本机输入不变，组合键结构不同的操作仍遵循目标系统规则。
- **登录启动**：用户登录桌面后后台启动到托盘，不包含开机首次登录界面；先将应用放到固定位置再开启。
- **自动共享**：启动后按已保存配置等待或连接；对端未上线时保持等待。手动停止后，本次运行不会再次自动启动。仅切屏模式则自动启用显示器控制。
- **托盘与退出**：macOS / Windows 左键打开主界面，右键显示切换、停止、恢复和退出菜单。关闭窗口仅隐藏到托盘，Mac 同时隐藏 Dock 图标；彻底退出使用托盘或 Dock 的退出选项。没有可用托盘时，关闭窗口会退出。

## 文件与目录传输

1. 配对并保持连接，进入 **文件传输**。
2. 将文件或完整目录拖入发送区，或点击区域选择文件，支持多选。压缩包作为普通文件发送，不自动解压。
3. 接收端确认邀请并选择保存位置，文件按原名直接保存，不增加外层任务目录。重名时选择 **替换、保留两者或停止操作**；目录替换为整体替换，不合并旧内容。
4. 可查看进度和速度、暂停、继续或取消。暂停 / 重启后，在发送端选择原任务的 **重新发送此任务**，接收端选择 **继续接收**，无需重新选择源文件。

传输采用流式读写，不将整个文件读入内存。文件通道独立加密，并进行 SHA-256 校验；控制延迟升高时会主动降速，以减少对键鼠的影响。实际速度取决于 Wi-Fi、磁盘、文件数量和校验等因素。

- 支持大于 4 GiB 的文件，但受目标文件系统限制。每批最多 100000 个文件和目录、64 层目录、256 个根项目；最多同时运行 4 个任务。
- 临时缓存位于接收位置的 `.deskflow-ddc-任务ID.partial`，传输完成前请勿移动或修改。取消接收会清理未完成缓存；移除记录不会删除已完成文件。
- 不支持符号链接、目录联接、设备文件等特殊类型，不保留权限、扩展属性或资源叉，不作为系统备份工具。
- 当前不提供系统文件复制粘贴或跨屏文件拖拽。
- 停止键鼠共享会断开控制连接，但已建立的文件传输可继续；需要停止文件任务时请单独暂停或取消。切到“仅切换显示器”模式会暂停未完成任务。

## Windows 锁屏与密码界面

普通模式无需管理员权限，但无法控制密码 / PIN 安全桌面。需要此功能时，在 Windows 接收端停止共享，进入 **共享设置 → 锁屏与登录界面控制**，安装后台服务并允许管理员授权，再开启 **允许控制安全桌面**、保存并重新共享。仅支持内置引擎，应用更新后需更新服务。

可从工作台或托盘锁定 Windows 接收端，或在键鼠位于 Windows 时按提供端的 **`Ctrl + Alt + Shift + L`**（Mac Alt 为 Option）。此功能通过已配对连接请求锁屏，不依赖模拟 `Win + L`。

服务不保存登录密码，只控制本应用启动的引擎。当前覆盖已登录用户锁屏后的控制，不包含开机首次登录、注销后登录或 BitLocker，不模拟 `Ctrl + Alt + Delete`。便携版删除前请先移除服务；系统策略和安全软件可能影响控制效果。

## Ubuntu Beta

目标系统为 Ubuntu 24.04 x86_64 / ARM64 + X11，请选择文件名带 `beta` 的 DEB 包。

```sh
sudo add-apt-repository -y universe
sudo apt update
sudo apt install ./实际文件名.deb
deskflow-ddc
```

以普通用户运行，不要使用 `sudo` 启动应用。完整共享要求 `echo "$XDG_SESSION_TYPE"` 为 `x11`，否则请注销并在登录界面选择 **Ubuntu on Xorg**。GNOME 托盘需要 AppIndicator 扩展。

配对需要默认且已解锁的系统密钥环。首次启动出现凭据错误时，可在 **Passwords and Keys（seahorse）** 中创建带密码的 **Password Keyring**，设为默认并解锁，再打开应用；无需删除配置或身份文件。

物理 DDC 需要 ddcutil 和 I²C 权限。系统存在 `i2c` 组时，可按以下方式配置，注销并登录后再检测：

```sh
sudo modprobe i2c-dev
sudo usermod -aG i2c "$USER"
# 注销并重新登录后：
ddcutil detect
ddcutil getvcp 60
```

没有 `i2c` 组时请按发行版规则配置权限，应用不会自动提权。虚拟机通常无法透传显示器 DDC/I²C，不能验证真实切屏；当前没有无需显示器配置的纯键鼠模式。

## 网络、隐私与问题反馈

- 完整共享需要两端可互通的网络，同一局域网最方便；mDNS 发现通常只在同一子网有效。访客网络、客户端隔离、VPN 或防火墙可能阻断发现，可手动填写主机名和备用 IP。
- 默认端口：控制 **TCP 49729**、键鼠 **TCP 24801**、发现 **UDP 5353**。文件传输会临时监听系统分配的 TCP 端口，需允许应用网络访问，仅开放固定端口不足以传文件。
- 已安装所需运行时后，共享不需要外网或云中转。Windows 缺少 WebView2 时，运行时安装可能需要联网。
- 配对密钥使用系统凭据存储；引擎私钥存放于应用数据目录。应用不记录按键内容、鼠标轨迹或剪贴板内容。文件任务记录保留文件名、路径和保存位置，以支持续传。
- 当前一对一共享，不提供远程桌面视频、USB 转发或自动唤醒。锁屏、睡眠恢复、不同 DPI 和显示器兼容性受系统、驱动及引擎限制。

**鼠标能动但不能点击，或键盘无响应时**，优先在仍可操作的一端停止共享；关闭主窗口不会停止共享。引擎返回提供端的按键为 Windows `Ctrl + Alt + Esc`、Mac 提供端 `Ctrl + Command + Esc`，只请求转移键鼠，不保证恢复画面；引擎失去响应时也可能失效。应用内“停止共享并恢复输出”不能保证在所有输入均失效时仍可触达。

反馈问题时，请从两端的 **活动记录 → 导出诊断日志** 导出日志，并附上应用 / 系统版本、提供端与接收端角色、接线方式及复现步骤。日志含设备名、局域网地址和文件任务信息，分享前请检查，不要公开配对码、私钥或完整配置。
